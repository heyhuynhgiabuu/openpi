# SDK 1.0.0 Upgrade Plan (pi-coding-agent 0.86.1 → 1.0.0)

Date: 2026-10-02. Status: proposed.
Scope: bump `@earendil-works/pi-coding-agent` and `@earendil-works/pi-ai` (both exact-pinned 0.86.1) to 1.0.0, absorb upstream breaking/behavior changes, update repo docs that are no longer true. Toolchain stays on TS 5.8.

## Evidence base

- Upstream releases between installed and target: 0.87.0, 0.87.1 (2026-09-21/22), 0.99.0–0.99.2 (2026-09-29/30), 1.0.0 (2026-10-01). Changelog read in full at tag `v1.0.0` (`packages/coding-agent/CHANGELOG.md`).
- Compile probe (scratch project, exact tarballs of both packages at 1.0.0, TS 5.8, `--strict --target ES2022 --module ESNext --moduleResolution bundler --skipLibCheck`): OpenPi's full root-entry import surface typechecks clean — `createAgentSession`, `SessionManager`, `SettingsManager`, `DefaultPackageManager`, `DefaultResourceLoader`, `ModelRuntime`, `AgentSessionEvent`, `ExtensionUIContext`, `getBuiltinModels(provider)` / `getBuiltinProviders` (`pi-ai/providers/all` subpath still exported), `AuthEvent/AuthInteraction/AuthPrompt`.
- Runtime probe: SDK 1.0.0 ships per-file ESM JS (`dist/index.js` → `./cli/args.js`); engines `node >=22.19.0`; Electron 41 bundles Node 24.17.0. Root export format unchanged vs 0.86.1 (`type: module`, `main ./dist/index.js`).
- TS7-native is NOT required: d.ts files use `.ts`-extension imports, which OpenPi's `skipLibCheck: true` (`tsconfig.json:7`) absorbs. TS7 only becomes relevant for the `./client` and `./experimental/plugin` subpath exports (now raw `src/*.ts`) or if `skipLibCheck` is ever dropped. Keep as a separate future toolchain track.

## Slices (each: own commit, full gates)

1. **Bump + compile gate.** `dependencies`: `@earendil-works/pi-coding-agent` → `1.0.0`, `@earendil-works/pi-ai` → `1.0.0` (keep exact pins). Fix what surfaces in `npm run typecheck` / `lint` / `test` / `smoke:electron`. Expected hot spots: known-event schemas in `src/lib/ipc/_full.ts` if a required field changed shape; `getBuiltinModels` generic inference over the provider union in `modelPricing.ts`.
2. **Format-tolerance fixtures.** Integration tests: (a) JSONL containing a `context_edit` entry flows through tree/history/usage without counting as a conversation message; (b) an `agent_before_settle`-shaped event passes the renderer union via the extension bucket. Locks 0.87.0 union expansion against regression.
3. **New-session timing.** Verify new-session → sidebar listing appears after first prompt (index refresh is event-driven on `entry_appended`/`agent_end`). No code change expected; add test if a gap shows.
4. **Docs truthing (same PR).** AGENTS.md "Pi Concepts You Must Understand" / "What Pi does NOT have", STATUS.md, ROADMAP non-goals note: MCP/codemode/tool-search are Pi built-ins as of 0.99.0. OpenPi surfaces them later via the SDK; do not build MCP management UI in this upgrade.
5. **Release.** CHANGELOG entry (user-facing: SDK 1.0.0, docs corrections), version bump, packaged smoke.

## Rollback

Revert the dependency-pin commit (exact pins make this one line per package). Sessions written under 1.0.0 may contain `context_edit` entries; 0.86.1-based OpenPi reads them as unknown-typed entries (duck-typed parser), so downgrade keeps sessions readable. `branch_summary`-style entries created by 0.99.x features are the same class.

## Uncertainties

- The probe covers the root-entry import surface only; repo-wide typecheck may surface additional drift (hence slice 1 gates).
- Renderer known-event schemas validate at runtime, not compile time — a changed required field would drop events silently; slice 2 fixtures + a manual session run (prompt, steer, compact, branch) cover this.
- MCP async connect changes event ordering early in a session; watch smoke + one manual cold start.
